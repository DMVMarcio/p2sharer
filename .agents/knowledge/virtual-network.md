# Virtual IPv4 network

`virtual_network.rs` owns main-process admission, app session leases and authenticated bounded loopback IPC. `virtual_network_driver.rs` owns Wintun/IP Helper/Windows Firewall operations; `virtual_network_policy.rs` parses and authorizes packets independently of hardware. `main.rs` routes the exact helper argument before Tauri initialization.

`RoomAppModel.prepareJoin` gates local entry before publishing presence; duplicate attempts share preparation and a closed/reset app cannot join after late completion. Tunnels prepare the native session even with no enabled rules. Each joined/prepared app holds a lease; disabling rules removes grants/routes/firewall allows while retaining the session. Leaving the final app closes IPC and tears down the virtual adapter session. Saved own definitions remain inactive. Active owner-authored remote grants require no client toggle.

Entering a tunnel app requests Windows administrator consent through `ShellExecuteExW` with `runas` to launch a transient helper from the current executable. Joined app leases retain that helper while toggles enable or disable permissions. Leaving the final app or closing P2Sharer shuts down the helper; a later session requires fresh consent. No Windows service, startup registration or executable copy to Program Files is created. The main application remains unelevated. Automatic tests/builds never launch the helper.

Shell activation runs on a Tokio blocking worker with balanced COM initialization
and `SEE_MASK_NOASYNC`, because that thread has no Windows message loop.
Ordinary shell error dialogs are suppressed while UAC consent remains enabled.

Each installation saves its randomly assigned private IPv4 in the app-local `virtual-network.json`. Allocation checks physical interface subnets and can choose from several private pools; regeneration requires all virtual scopes to be off and takes the same machine-wide Windows singleton lock as the helper. Peers' addresses remain bound to authenticated room actors. Duplicate addresses and local subnet conflicts fail closed rather than replacing another actor's routes. The virtual network is exclusive to one P2Sharer process per Windows machine, including other logged-in sessions. Definitions are saved without permissions, live flows or automatic reactivation.

The signed, unchanged AMD64 Wintun 0.14.1 DLL is embedded with its original prebuilt license, pinned archive/DLL checksums and recorded provenance under `src-tauri/resources/wintun/`. Runtime extraction verifies exact embedded bytes and retains a read-only sharing guard while dynamically loaded. The helper uses only the permitted public API, owns one named adapter, assigns a host-only IPv4 address and installs exact per-peer host routes. It does not change DNS, default routes, physical adapter configuration or Internet routing. Startup cleans stale virtual entries only on the application-owned adapter. Firewall allows are restricted to the virtual local address, current virtual peer addresses and enabled TCP/UDP ports or echo ping. The helper removes its address, routes and firewall rules on normal shutdown. A helper-created adapter is also removed by Wintun's close API; an existing recovered adapter is retained without active entries.

Main/helper IPC requires a random 256-bit token before configuration. Control messages have bounded sizes, settings revisions and acknowledgements. The helper does not accept arbitrary executable paths, commands, interfaces, routes or addresses. Packet and IPC queues, frontend pending sends, native credits, scopes, peers, flows and fragment caches are bounded. Keepalives and timeouts detect loss; late startup cannot resurrect a removed scope. Process handles track helper shutdown so updater preparation waits for it to exit, without terminating it. Idle IP regeneration gracefully stops the prepared session, allocates the new identity under the singleton lock and resumes leases with a new elevated helper and fresh consent. The current Windows user and the main WebView are trusted; this is not isolation from malicious processes in an authorized local session.

Startup consumes the initial configuration before acquiring the native lock or configuring Windows. A rejected setup sends its stage-specific error, shuts down the sending half and performs a bounded drain before closing, preserving diagnostics instead of resetting a socket with unread configuration. The headless helper initializes the canonical session logger and panic hook; its native errors are recorded independently of the main process log. A startup reset still requires investigation of that helper log and is not proof of a port conflict.

Firewall COM interfaces must be released before their owning thread uninitializes COM, including adapter setup failure paths. The native firewall owns its apartment guard after its interface field so Rust's field destruction order enforces this lifetime. Construction alone is read-only; cleanup runs only after configuration was attempted. Automatic regression coverage opens and releases real firewall interfaces on a fresh thread without configuring rules or installing an adapter.

After reading the IPv4 interface row, explicitly reset `SitePrefixLength` to zero before `SetIpInterfaceEntry`; Windows can return a nonzero value from the getter even though the setter rejects it for IPv4 with `ERROR_INVALID_PARAMETER`. The localization catalog recognizes the complete stage-specific interface error and preserves its numeric Windows code.

The driver MTU is 1280. Native admission validates the IPv4 header/checksum, exact sender address, local destination and current app membership. New incoming flows require an owner's active port grant; new outgoing flows require an active owner-authored remote grant. Authorized reverse flows do not expose arbitrary ephemeral local ports. Policy revisions revoke affected flows while unrelated membership changes preserve existing flows. Fragments require an authorized first fragment and cannot overlap; caches expire and are resource-limited. Raw IPv6, IPv4 options, forwarding to other networks, broadcast/multicast discovery and non-TCP/UDP protocols other than echo ping are not supported.

Room IP packets use the dedicated binary unordered WebRTC datagram channel with zero retransmissions, independent of reliable proxy/image queues. Binary Tauri Channels and raw IPC avoid Base64 on the active packet path. Congested datagram queues drop packets rather than retaining stale traffic; TCP applications retain their own IP-level recovery. Native policy checks remain authoritative on every received packet. Separate SCTP channels still share the peer connection congestion budget; this implementation does not establish Hamachi/Radmin performance parity. Virtual counters count IP packet bytes and native/bridge drops, whereas legacy proxy counters count socket payload bytes. Applications must bind the virtual address or a wildcard interface; a loopback-only service should keep using a proxy rule. Rule revocation stops authorized virtual traffic; external applications own their sockets and may detect a broken TCP connection through their usual timeouts.

Automatic tests cover native ACLs, return flows, fragment handling, conflicts, limits and revocation, plus frontend persistence, automatic remote reconciliation, owner binding, snapshot rejection, cancelled activation and helper failure. Builds/tests do not launch the helper or install the adapter. User-operated checks on two Windows x64 computers remain required for UAC on app entry, toggle reuse within a joined session, fresh consent after leaving/reopening or restarting P2Sharer, cancellation, driver installation, route/firewall teardown, ping, a real TCP/UDP server, multi-app operation and reconnect behavior. Both users join the same app, the server enables its virtual rule and joined clients automatically receive access to that active rule before using the advertised virtual IP. Hardware behavior and cross-machine throughput remain unverified until those checks.
