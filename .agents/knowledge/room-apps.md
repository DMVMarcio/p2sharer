# Room Apps

`src/apps/registry.ts` registers app definitions with a model factory and a lazy view loader. New bundled apps can register their own models and views without changing the transport or room service. Each launch creates a UUID instance; several instances of either kind may coexist. `RoomVideoContainer` renders each instance in the same grid or spotlight stage as peer cards. The app UI is rendered locally for every participant and exchanged as state over the room's `room_apps` Trystero action. No screen video is sent for app cards.

The header Apps button opens `AppsModal`, whose icon, description, and banner come from the registry metadata. App cards are clipped to the same grid or spotlight bounds as transmissions. `src/apps/apps.css` owns their responsive layout and containment. YouTube places the player and queue on the left and search on the right when the card is wide; a narrow card offers a local pane switch. Theatre mode is local UI state and expands the player only within its card. The activity header keeps its normal height above the video, while playback controls appear on video hover or keyboard focus. It does not send layout changes to peers. The app card header has a direct Back to grid action. Its three-dot menu contains Leave activity, which unmounts the local app and removes local presence without ending the shared instance, and End for everyone. Grid rows remain vertically centered when app slots are present and fit the viewport; safe alignment keeps overflowing rows scrollable from the top. Local lifecycle callbacks publish one signed chat notice per app start or stop, including the actor and app kind. Remote lifecycle events never republish those notices.

`PersistentRoomApps` mounts each joined app view once in a stable layer within `RoomVideoContainer`. Grid, spotlight, and tray render measured slots; the app card changes position and compact styling without moving or remounting its iframe. Participation is opt-in per instance. Outside participants see a join panel and do not mount the app view or YouTube iframe; joined participants see a compact video preview in unfocused cards. `RoomAppsService` exchanges actor-bound presence events, answers late-peer sync with local presence, and clears disconnected actors. Header avatar initials follow the existing room slot colors and show names through the common tooltip. The YouTube IFrame API's native play and pause events are published to the shared model when they differ from room state. Volume is local per device. YouTube's embed may still display its own metadata and related-video controls; its API does not provide a supported way to remove them.

`GroupRoomManager` subjects the action to its existing direct peer verification and admission wrapper. The action carries start, stop, generic app data, and targeted sync messages. `RoomAppsService` owns instance lifecycle and routes data to the registered model. Peers exchange snapshots when a participant arrives; notes use Yjs CRDT updates so simultaneous edits converge. YouTube state uses a Lamport clock and actor tie break; the smallest joined actor publishes playback position every ten seconds. Each joined player independently checks drift on the same interval, projecting the shared position from local receipt time. Routine drift up to four seconds is tolerated, with an eight-second seek cooldown. Play/pause and manual seek events request tighter immediate correction around 0.75 seconds. Resuming after buffering checks drift before the leader can publish another position. Playback speed is not modified. Browser autoplay rules and network delay prevent frame accurate synchronization.

The notepad uses Tiptap with Yjs XML fragment updates for shared rich content and Yjs awareness for remote caret labels and selections. It opens local `.html`, `.md`, and `.txt` files through native Tauri commands in `src-tauri/src/note_files.rs`; saving uses HTML to preserve rich formatting. Opening a file replaces the shared document. The file itself is not transmitted, only the edited document state. The legacy Yjs plain-text field remains in the model for compatibility with existing tests and older snapshots. The YouTube app accepts video and playlist links without an API key and shows preview results before any queue mutation. Video titles use YouTube's oEmbed endpoint; playlist titles, counts, and thumbnail IDs come from public Invidious instances when available. Keyless text search and playlist import use the public Invidious API through a fixed list of instances from its official catalog, validating IDs and titles before they enter shared state. These public services may become unavailable; the UI offers external YouTube search as a fallback. Search terms are sent to the selected Invidious instance, while the shared room message carries only selected video IDs and titles. The player loads Google's IFrame API only after the local actor joins a YouTube activity. CSP allows the required YouTube frame, oEmbed requests, Invidious API requests, and thumbnails. A transparent local hit area handles click-to-toggle and prevents pointer hover from reaching the YouTube iframe, avoiding its hover UI over the app controls. The custom playback deck has a local draft seek state so the visual thumb and time tooltip follow dragging immediately; a completed seek is then sent to the room. Queue moves preserve the currently selected entry and playback position. Repeat-all, repeat-one, shuffle, and remove-played modes are synchronized in the YouTube model. The smallest joined actor advances at video end and publishes playback time, allowing controller handoff after a participant leaves. The embed requests captions off with `cc_load_policy: 0`; the local caption toggle also attempts to load/unload the YouTube captions module when present. That module control is not documented as a supported caption toggle and may stop working if YouTube changes it. Google's IFrame API no longer supports querying or setting playback quality, so the app cannot present a functional quality selector.

Room app state currently exists only in the memories of connected admitted peers. If every peer leaves, app instances and notes disappear unless a participant saved a note locally. This follows the room's P2P only state policy.
