# Shared Browser

`browser_model.ts` binds the browser host to the room app's immutable `createdBy`, independently of room authority. Joined participants send actor-bound commands to that host over the existing admitted app transport. The host serializes input, rejects replayed sequences and stale tab/session targets, and invalidates queued commands across membership changes. Pending motion is coalesced per actor between button/key/navigation barriers; the authoritative virtual cursor updates independently of slow renderer completion. Mouse, keyboard and text renew a single control lease; idle control expires after one second, held gestures have a loss timeout, and local host input preempts remote control. Held keys/buttons are released on handoff. Script dialog answers bypass the input queue because the originating click can be paused by the dialog itself. The browser creator can stop the session without removing the room app or discarding its persistent profile.

`shared_browser.rs` creates isolated WebView2 windows for tabs. Every window starts blank and is configured before navigating to third-party content; new sessions without saved pages and new tabs open Google. App-generated browser labels have no capabilities, application commands explicitly reject browser callers, and WebView2 web messages are disabled. Navigation accepts bounded HTTP(S) URLs and blank pages, excluding application origins. Native methods expose typed commands rather than arbitrary scripts or DevTools methods. Native release emits events only for buttons actually held, preventing an idle handoff from synthesizing a right click. `browser_dialogs.rs` retains script dialog COM deferrals on the UI apartment and sends bounded text to the canonical application dialog. Downloads require a host-operated Save dialog.

`browser_capture.ts` uses the canonical `NativeVideoBridge` and a generation-specific native capture session. WGC captures the active app-owned tool window, positioned outside the virtual desktop, without taskbar presence or activation; inactive tabs remain hidden. This internal source bypasses only the picker's tool-window exclusion after checking process ownership and visibility. Pixels use the authenticated binary WebSocket bridge rather than per-frame DevTools screenshots or Base64 IPC, keeping capture outside the input operation lock. Native encoder preferences, GPU/readback scaling, bounded delivery, pressure feedback and decoder fallback follow ordinary native screen capture. Tab changes replace the video track while retaining audio and peer connections; profile changes update frame rate and dimensions in place. Native session teardown is also bound to browser closure. Controller3 raw-pixel bounds and explicit rasterization scale keep the logical viewport/input at 1280×720 while producing 720p or 1080p. CDP viewport emulation is not used; native scaling persists across navigation. The optional video probe runs outside the input operation lock.

`browser_navigation.rs` records top-level WebView2 navigation start/completion per tab, guarded by native session generation and navigation ID. Loading events go directly to the trusted shell and then authenticated room snapshots; metadata refresh preserves concurrent navigation state. The page progress bar is indeterminate. `browser_favicon.rs` reads bounded native PNG icons, resizes them and includes them in host snapshots; viewers never fetch favicon URLs independently. Native fullscreen hides tabs and uses an overlay toolbar with the shared idle-controls hook; focused controls remain accessible while the page keeps its full area. Native fullscreen transitions are serialized; failed native exits restore dialog interactivity for retries. Fullscreen dialog presence suppresses shell titlebar chrome independently of native resize events.

Reading targets 720p/15 with detail-oriented encoding. `browser_quality.ts` starts playback at 720p/30 and adapts up to the host's saved ceiling using measured native processing and bridge cost. Playback detection runs once per second with a fixed bounded isolated-world probe and three-second pause grace period. Unsupported/protected players can require the host's Video override. Hardware codec availability, protected content and real throughput require interactive desktop verification; native JPEG remains the canonical encoder fallback. WebRTC applies per-viewer congestion adaptation independently of host capture quality.

SDP/ICE use app messages, the room’s Internet/LAN RTC configuration and canonical codec preferences. ICE is buffered until SDP publication; failed/disconnected connections renegotiate. Browser process-tree WASAPI capture owns an independent stop flag and event name, preserving ordinary screen audio capture. Viewer audio uses `AudioContextManager`; host playback remains native. Media, cookies, local paths and extension settings are absent from room snapshots.

One browser session can run per application process, with up to sixteen tabs. Persistent data lives under the dedicated app-local `SharedBrowser` directory, separate from the shell and personal browsers. URL lists and the active tab are saved locally; reopening reloads pages rather than restoring in-memory DOM state. Temporary sessions use unique directories and InPrivate mode. Reset selects a fresh profile generation and retries deletion of the previous directory after closing its WebViews; downloaded files are retained. Cache, history and site data have separate cleanup actions. Extensions load from a host-selected unpacked folder and support listing, enabling, disabling and removal; the source folder must remain available.

Browser detachment is disabled; native monitor full screen through the canonical fullscreen dialog and website full screen remain available. Closing/leaving the host session stops its browser/media, without host migration. New-window links become shared tabs; retaining popup opener relationships, extension toolbar popups, store installation, browser sync, remote native file pickers and arbitrary system permission dialogs are outside this implementation. Protected media and individual extension/site compatibility require interactive desktop checks.

Model and signaling regressions run without hardware. User-operated checks should cover two desktop instances, simultaneous input and host takeover, typing/IME/paste, tab navigation, website dialogs and full screen, audio alongside screen sharing, profile persistence/reset, temporary session closure and unpacked extensions. Automated packaging and policy tests do not establish live WebView rendering or cross-machine compatibility.
