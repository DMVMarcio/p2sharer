# Shared Browser

`browser_model.ts` binds the browser host to the room app's immutable `createdBy`, independently of room authority. Joined participants send actor-bound commands to that host over the existing admitted app transport. The host serializes input, rejects replayed sequences and stale tab targets, and invalidates queued commands across membership changes. Mouse, keyboard and text renew a single control lease; idle control expires after one second, held gestures have a loss timeout, and local host input preempts remote control. Held keys/buttons are released on handoff. Script dialog answers bypass the input queue because the originating click can be paused by the dialog itself.

`shared_browser.rs` creates hidden WebView2 windows for tabs. Every window starts blank and is configured before navigating to third-party content. App-generated browser labels have no capabilities, application commands explicitly reject browser callers, and WebView2 web messages are disabled. Navigation accepts bounded HTTP(S) URLs and blank pages, excluding application origins. Native methods expose typed commands rather than arbitrary scripts or DevTools methods. `browser_dialogs.rs` retains script dialog COM deferrals on the UI apartment and sends bounded text to the canonical application dialog. Downloads require a host-operated Save dialog.

`browser_media.ts` captures the active viewport through native DevTools JPEG screenshots into a manually paced canvas track and sends video through one targeted WebRTC connection per joined viewer. The logical viewport and input coordinates remain 1280×720; device scale changes produce 720p or 1080p output without changing layout dimensions. Reading targets 720p/15 with detail-oriented encoding. `browser_quality.ts` starts playback at 720p/30, upgrades on sustained measured capture headroom up to the host's locally saved ceiling (1080p/30 by default, optional 1080p/60), and downgrades under sustained capture load. Capture time is included in the frame interval; frames never queue. Playback detection runs once per second using a fixed bounded probe in isolated frame worlds, including open shadow roots, with a three-second pause grace period. Unsupported/protected players can require the host's explicit Video override. These are target rates, not a verified sustained video-capture capability: JPEG/IPC/decoding still constrain throughput. WebRTC applies per-viewer congestion adaptation independently of the host capture policy.

SDP/ICE use app messages, the room’s Internet/LAN RTC configuration and canonical codec preferences. ICE is buffered until SDP publication; failed/disconnected connections renegotiate. Browser process-tree WASAPI capture owns an independent stop flag and event name, preserving ordinary screen audio capture. Viewer audio uses `AudioContextManager`; host playback remains native. Media, cookies, local paths and extension settings are absent from room snapshots.

One browser session can run per application process, with up to sixteen tabs. Persistent data lives under the dedicated app-local `SharedBrowser` directory, separate from the shell and personal browsers. URL lists and the active tab are saved locally; reopening reloads pages rather than restoring in-memory DOM state. Temporary sessions use unique directories and InPrivate mode. Reset selects a fresh profile generation and retries deletion of the previous directory after closing its WebViews; downloaded files are retained. Cache, history and site data have separate cleanup actions. Extensions load from a host-selected unpacked folder and support listing, enabling, disabling and removal; the source folder must remain available.

Browser detachment is disabled; native monitor full screen through the canonical fullscreen dialog and website full screen remain available. Closing/leaving the host session stops its browser/media, without host migration. New-window links become shared tabs; retaining popup opener relationships, extension toolbar popups, store installation, browser sync, remote native file pickers and arbitrary system permission dialogs are outside this implementation. Protected media and individual extension/site compatibility require interactive desktop checks.

Model and signaling regressions run without hardware. User-operated checks should cover two desktop instances, simultaneous input and host takeover, typing/IME/paste, tab navigation, website dialogs and full screen, audio alongside screen sharing, profile persistence/reset, temporary session closure and unpacked extensions. Automated packaging and policy tests do not establish live WebView rendering or cross-machine compatibility.
