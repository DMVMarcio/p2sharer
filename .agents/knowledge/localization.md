# Application localization

The app uses one synchronous i18next instance in `src/i18n/index.ts`, bundled English and Brazilian Portuguese JSON catalogs, and the canonical `useLocale` subscription. First launch invokes `get_system_locale` in the Rust host before mounting React. Portuguese variants select `pt-BR`; English variants and unsupported primary languages select `en`. A valid saved `p2sharer_language` preference takes priority on later launches. The Application settings Select edits a draft owned by SettingsModal. Only Save Settings applies and persists it after the form passes validation; closing discards it. Keep the selector free of an explanatory subtitle. Document language, window captions and locale-sensitive formats update with the choice. Storage events synchronize detached WebView2 windows without reopening streams or editors.

Use `t(key, values)` for app copy and `useLocale()` in components that display it. Migrated `message.*` keys are stable hashes of source copy; new semantic keys are also supported. Both catalogs must have identical keys and interpolation variables. Use i18next count plurals for count-sensitive messages. Keep whole sentences together so translations can reorder interpolated values. Module-level labels and retained context-menu actions use getters to avoid freezing the language. Text stored in UI status/error/toast state can use `localizeText` at presentation; never apply that helper to authored data. Native diagnostics without a catalog entry use `localizeError` for localized fallback copy.

Signed room notices retain their existing wire format. In particular, built-in activity `protocolLabel` values are stable and independent of translated registry labels. `SystemNoticeText` renders structured notice metadata in the receiving client's language without changing the signed body. Usernames, room names, chat messages, shared documents, saved queue names, captured application names and external video titles remain authored content.

The notepad placeholder reads translation dynamically. Language changes update its editor attributes and decorations without rebuilding the collaboration document or editor. Native note dialog titles, filters and suggested filenames receive the current app language; standard Windows dialog buttons and the caption system menu remain managed by Windows.

Offline emoji accessible names and search use a bundled Unicode CLDR subset for both languages. `tools/generate-emoji-labels.mjs` pins the upstream revision and records the license under `public/emojis/`. Every picker entry must have names in both catalogs. Original English shortcodes and Portuguese aliases remain searchable.

`localization.test.mjs` checks first-run detection, saved preference priority, storage synchronization, mounted notice updates, authored name preservation, plurals, numeric formatting, catalog parity and source key coverage. Settings and titlebar tests exercise the real canonical selector and native title updates. Chat notice regressions verify language-independent signed activity copy. Frontend tests preload a deterministic Portuguese navigator; production detection does not depend on that fixture.
