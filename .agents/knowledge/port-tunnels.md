# Native port tunnels

`src/apps/tunnel_model.ts` registers a room app through the canonical registry. Each joined activity owns one native scope. Saved definitions are device-local under `p2sharer_port_tunnels_v1`; activation and socket sessions are never persisted. Models sharing the same storage synchronize definition edits and revoke changed exports. Leaving the activity clears activation, whereas temporary remote departure removes that peer's mappings and access. Rejoining requires manual activation; interrupted TCP sessions are not replayed.

Legacy rules remain loopback port proxies. A published proxy rule grants access only to a fixed TCP or UDP port at the owner's `127.0.0.1`. Joined clients automatically bind a free loopback port for each active remote proxy, then connect ordinary programs to the displayed address. The Windows-assigned port avoids claiming a local service port. The legacy explicit-binding API retains saved port preferences. Virtual rules use the native virtual IPv4 network described in [virtual-network.md](virtual-network.md), with fixed ports or all TCP/UDP ports and echo ping. LAN discovery, arbitrary destination hosts and detached tunnel windows are outside the current scope. Joined members advertise enabled and disabled definitions; the participant list shows only enabled rules, and automatic reconciliation grants and revokes access according to the authenticated owner. Own rules still require manual activation.

Owner advertisements are applied under the authenticated direct sender's actor, including sync snapshots. Forwarded claims cannot edit another owner's rules. Socket packets are targeted through the admitted binary transport and accepted only between joined activity members; room actions remain the control and compatibility path. Snapshots cannot execute socket commands. `RoomAppModel.setParticipants` supplies membership teardown independently of React visibility, compact layouts, filters and remounts.

`src-tauri/src/port_tunnel.rs` owns sockets, per-scope membership and export generations. All commands require the main window. Exports must match the current local generation before a connection is created; editing, disabling, membership removal and scope teardown cancel existing sessions. Async binds/connects are rechecked or cancelled to prevent late resurrection. Global sessions are capped at 32, scopes at 24, and forwards/exports at 32 per scope. Connections use random 128-bit session identifiers and bounded queues. TCP uses ordered sequence checks, up to 16 outstanding reads per direction and acknowledgements after local socket writes. UDP uses independent datagrams with a bounded replay window, allowing reordering and loss without application acknowledgements. TCP supports half-close. Stalled handshakes/acknowledgements expire; idle UDP sessions expire after 60 seconds.

The native-to-WebView bridge uses a scope-bound binary Tauri Channel and raw return IPC through `peer_payload.rs`. Dedicated WebRTC data channels carry reliable ordered proxy controls/TCP separately from unordered UDP with zero retransmissions. Both directions retain main-window checks and native scope/member/export authorization. UDP preserves datagram boundaries, including empty datagrams. Oversized UDP frames exceeding the negotiated SCTP message limit retain room-action fragmentation as a compatibility path. Congested UDP queues drop datagrams. TCP uses 16 KiB chunks; UDP payloads are limited to the IPv4 datagram maximum. Native counters expose payload bytes sent/received and current sessions, not negotiated throughput or per-tunnel latency.

`test/unit/port_tunnel.test.ts` covers persistence, owner isolation, snapshot restrictions, lifecycle revocation and native failures. Native `port_tunnel::tests` exercises real loopback TCP/UDP forwarding, TCP half-close, empty/large UDP datagrams, revocation and resource limits. These tests do not establish cross-machine throughput or game compatibility; those require the user's interactive desktop checks.
