# Native port tunnels

`src/apps/tunnel_model.ts` registers a room app through the canonical registry. Each joined activity owns one native scope. Saved definitions are device-local under `p2sharer_port_tunnels_v1`; activation and socket sessions are never persisted. Models sharing the same storage synchronize definition edits and revoke changed exports. Leaving the activity clears activation, whereas temporary remote departure removes that peer's mappings and access. Rejoining requires manual activation; interrupted TCP sessions are not replayed.

The first stage is a loopback port proxy, not a virtual network adapter. A published rule grants access only to a fixed TCP or UDP port at the owner's `127.0.0.1`. Clients bind their own loopback port (or request an ephemeral port with zero), then connect ordinary programs to that address. The local port preference is saved per tunnel UUID without restoring activation. IP virtualization, all-port access, LAN discovery, arbitrary destination hosts and detached tunnel windows are outside this stage. Joined members advertise both enabled and disabled definitions; only enabled rules enter native permissions.

Owner advertisements are applied under the authenticated direct sender's actor, including sync snapshots. Forwarded claims cannot edit another owner's rules. Socket packets are targeted through the existing admitted `room_apps` action and accepted only between joined activity members. Snapshots cannot execute socket commands. `RoomAppModel.setParticipants` supplies membership teardown independently of React visibility, compact layouts, filters and remounts.

`src-tauri/src/port_tunnel.rs` owns sockets, per-scope membership and export generations. All commands require the main window. Exports must match the current local generation before a connection is created; editing, disabling, membership removal and scope teardown cancel existing sessions. Async binds/connects are rechecked or cancelled to prevent late resurrection. Global sessions are capped at 32, scopes at 24, and forwards/exports at 32 per scope. Connections use random 128-bit session identifiers, ordered sequence checks, bounded queues, one outstanding data frame per direction and acknowledgements after local socket writes. TCP supports half-close. Stalled handshakes/acknowledgements expire; idle UDP sessions expire after 60 seconds.

The native-to-WebView bridge uses main-targeted Tauri events; socket data returns through bounded IPC and the existing reliable WebRTC room action. UDP preserves datagram boundaries, including empty datagrams, but its outer transport is reliable and ordered and may add latency under packet loss. Congested UDP queues drop datagrams. TCP uses 16 KiB chunks; UDP payloads are limited to the IPv4 datagram maximum. Native counters expose payload bytes sent/received and current sessions, not negotiated throughput or per-tunnel latency.

`test/unit/port_tunnel.test.ts` covers persistence, owner isolation, snapshot restrictions, lifecycle revocation and native failures. Native `port_tunnel::tests` exercises real loopback TCP/UDP forwarding, TCP half-close, empty/large UDP datagrams, revocation and resource limits. These tests do not establish cross-machine throughput or game compatibility; those require the user's interactive desktop checks.
